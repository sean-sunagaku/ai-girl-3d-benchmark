## これまでの追加実行との違い（重要）

**コーディネーターと参加モデルが同一の Claude Code セッションです。** Kimi・Terra の実行では、
コーディネーターが別のハーネスへ課題文を渡して制作させました。今回はユーザーがこのセッションへ直接
依頼したため、同じセッションが次の順で両方の役割を担当しました。

1. コーディネーターとして、リポジトリの `README.md`、`AGENTS.md`、`docs/`、`scripts/`、`viewer/`、
   共通の課題文2件（`01-procedural.md` と `02-photo-textured.md`）、2026-10-25・2026-10-27 の
   コーディネーター側記録（各日の `README.md`、`run.json`、`viewer-checks.json`、`harness/`）を読みました。
2. `scripts/prepare_case.py` で `.work/` 内に独立した作業場所を作り、入力5件と課題文のハッシュを照合しました。
3. 参加モデルとして、その作業場所の `PROMPT.md` を課題として制作しました。
4. コーディネーターとして、収録・独立コピーでの再ビルド・技術検査・GLB書き出しを行いました
   （[coordinator_validate.py](coordinator_validate.py)）。

このため、次の点が他の参加モデルと異なります。成果物を見比べるときの前提として明記します。

- 初回の制作を始める前に、追加版の課題文（写真テクスチャを後で許可する内容）を読んでいました。
- 初回の制作を始める前に、検査スクリプト `scripts/inspect_scene.py`（人物だけのGLB書き出しを含む）と
  HTMLビューアーの存在を知っていました。髪の `Hair_Export_Proxy`（レンダーには写らないリボンメッシュ）は、
  メッシュしか運べない書き出し形式でも髪型が残るよう、この知識を踏まえて参加モデルが入れたものです。
- 2026-10-27 のコーディネーター記録にある、Terraの成果物の短い説明文（手のない閉じた袖、簡略化したカフェ）を
  読んでいます。
- 追加版で使う写真投影のコード（`fable/photo.py`）の下書きを、初回の最終ビルドの実行中に書き始めました。
  置き場所は作業場所の外で、初回の作業場所と収録物には入っていません。初回のコードは最終ビルドの開始後に
  変更していません。追加版の作業場所は、初回の最終ビルドが終わってから用意しました。
- 追加版は、作業場所の用意から最終ビルドの完了まで約25分でした（初回は約2時間24分）。同じセッションが
  続けて制作したため、初回のコードと写真の計測結果を覚えた状態で追加版を始めています。

**読んでいない／見ていないもの:** 他の参加モデルの `build.py` などの制作コード、各モデルの `README.md`、
レンダー画像、プレビュー画像、`scene-report.json`、`validation.json`、Blenderシーン、GLB。

## 課題文の渡し方

`procedural/fable-5.2/PROMPT.md` は共通の `01-procedural.md` と、`photo-textured/fable-5.2/PROMPT.md` は
`02-photo-textured.md` とバイト一致します。セッションは作業場所のファイルをそのまま読みました。
シェル経由の貼り付けはしておらず、末尾改行の欠落はありません。

ユーザーからこのセッションへの発言は次の2件です。どちらも課題文ではなく、実行全体への指示です。

> フェーブル5.2バージョンの女の子の3Dベンチマークの作成の方でもお願い。目標を作った上で、最後まで全部やりきってほしい。

> 続き頼む！

2件目は継続指示です。14:22 に利用上限の通知でセッションが止まり、ユーザーが 14:24 に送りました。
そのとき追加版は最終ビルドの実行中で、コードは 14:18 に確定済みでした。止まっていた間に進んだのは
そのビルドだけです。再開後のモデルと reasoning effort は停止前と同じで、制作内容に触れる指示はありません。

14:36 に、コンテキストの自動要約が1回入りました。両段階の最終ビルドと制作メモの確定より後で、
それ以降はコーディネーターとしての検証と記録だけを行っています。

制作中、デスクトップアプリから「進捗を短く伝えて続けてください」という定型の通知が繰り返し届きました。
課題の内容を変えるものではありません。追加のエージェント（サブエージェント）は使っていません。
画像生成・3D生成サービス、追加のモデルやテクスチャのダウンロードも使っていません。

## 課題文との関係で記録しておく判断

- 課題文は「他の参加者と同条件の4モデル比較」「他の参加者の成果物を読まない」としています。
  上の「読んでいない／見ていないもの」のとおり制作物は見ていませんが、コーディネーター側の文書は読んでいます。
- 手と前腕は、配布された `base.obj`（上半身メッシュの元になったCC0のMakeHuman全身）から同じ切り出し規則で
  取りました。追加のダウンロードではありません。
- 初回では、写真は目で見ることと、ランドマークの画素位置・大まかな領域の平均色を測ることにだけ使いました。
  写真の画素は、どのテクスチャ・材質・背景・レンダーにも入っていません。
- 追加版の `build.py` は、初回の保存シーンを読み込まず、配布された入力から全体を作り直します。
  課題文が「以前のシーンを素材にする場合」に求めている `source-character.blend` は、制作中の作業場所には
  参照用として置きましたが、`build.py` は読みません。初回の `character.blend` とバイト一致するため、
  収録物からは外しています。独立コピーでの再ビルドも、このファイルを含めずに実行しました。
